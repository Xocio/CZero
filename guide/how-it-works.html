工作原理 ​

本页说明 CZero 的运转方式，帮助你在判断"任务是否正常执行"时有据可依。

总览 ​

CZero 没有常驻的 Java 服务。它把职责拆成三段：安装时准备好配置，开机时拉起一个极轻量的调度进程，平时由这个进程按配置在后台触发各项任务。

安装  ──►  开机  ──►  运行
选语言/继承配置   拉起调度进程   按 config.json 定时触发清理

常驻的只有调度进程，且绝大多数时间处于休眠，到点才唤醒并派发任务；清理器本身用完即退，不占用后台资源。

安装时 ​

刷入时会用音量键问你两件事：

  1. 选择语言 —— 音量上 = English，音量下 = 中文；约 60 秒无按键则默认中文。
  2. 是否继承旧配置 —— 选择继承时，你的规则、白名单、应用名单原样沿用，config.json 会和新版默认值合并：改过的值保留，新版新增的选项自动补齐。只有旧配置已经损坏、无法合并时才会退回默认值。

安装完成后会打开下载页，方便顺手装配套应用。

开机后 ​

系统启动后，模块自行完成权限修正与状态初始化，随后拉起调度进程。其运行状态可在 CZeroX 主页查看；若未正常启动，也可在该处一键重启。

若启用了精细化压制的相关开关，开机阶段会额外完成一次系统压制能力的设置；其余情况下该步骤直接跳过。

任务如何触发 ​

  • 按本地时间调度 —— 所有任务依设备当前时区的时间触发，无需接触 cron 表达式。
  • 不会重入 —— 上一轮尚未结束时，本轮自动跳过。
  • 休眠错过会补执行 —— 设备深度休眠期间错过的任务，唤醒后补执行一次；同一任务仅补一次，不会积压为连续多轮。
  • 修改即时生效 —— 调度进程会感知 config.json 的变更并自动重新加载，无需重启。
  • 配置错误不影响服务 —— 整份配置无法解析时保留上一份有效的任务表；若仅某一项调度书写有误，则只跳过该项，其余照常执行。

一次清理的执行过程 ​

以微信缓存清理为例：

  1. 到点触发，先判断该应用当前状态；
  2. 若其正处于前台，或前台为游戏，则本轮跳过；
  3. 否则执行清理，受增强模式与时序屏障约束；
  4. 更新统计，按需写入日志，并将进度与结果通知 CZeroX。

为什么这样设计 ​

  • 无常驻服务 —— 只在需要时被唤起，平时不占内存与 CPU。
  • 单一配置源 + 热重载 —— 配置与行为一一对应，改完即生效，且坏配置不会拖垮服务。
  • 原生前端解耦 —— CZeroX 只读写配置文件，与模块彻底解耦，不装应用模块也能独立运行。
