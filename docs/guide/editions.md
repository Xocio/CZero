# 版本选择

CZeroX 提供两个版本，面向不同的授权方式。两者的清理规则、调度模型与大部分功能一致，区别在于**如何取得系统权限**以及由此决定的功能范围。

| | **Root 版** | **Shizuku 版** |
|---|---|---|
| 授权方式 | Magisk / KernelSU / APatch | Shizuku |
| 是否需要模块 | 需要，由模块负责调度与清理 | 不需要，清理程序与规则随应用自带 |
| 安装 | 刷入模块 zip，再安装 CZeroX | 仅安装 CZeroX，启动 Shizuku 后授权 |
| 最低系统 | Android 9 | 以 Shizuku 的要求为准 |

## 功能差异

| 功能 | Root 版 | Shizuku 版 |
|---|---|---|
| 微信 / QQ / 抖音清理、其他应用清理 | 支持 | 支持 |
| 自定义规则、白名单、规则源、应用缓存清理 | 支持 | 支持 |
| 后台压制、空文件夹清理、回收站 | 支持 | 支持 |
| 文件归类 | 支持，免费使用 | 支持，BETA，捐赠解锁 |
| Zero 智能助手、垃圾扫描、清理趋势 | 支持 | 支持 |
| F2FS 垃圾回收 | 模块自带方案，可调整触发条件 | 使用系统空闲维护，不提供触发条件的调整项 |
| fstrim | 支持 | 支持 |
| 精细化压制 | 支持（需 LSPosed） | 不支持 |
| 存储页（器件寿命、实时读写速率、性能测试） | 支持 | 不支持 |
| 清理应用内部数据目录 | 支持 | 取决于 Shizuku 的启动方式，见下文 |

::: tip 为什么有这些差异
Shizuku 提供的是受限的系统权限：与存储器件底层节点相关的功能（F2FS 状态、器件寿命、性能测试）以及依赖系统框架的精细化压制无法在该方式下使用。这是权限模型决定的，并非功能缺失。
:::

## 如何选择

- 设备已 Root：选择 **Root 版**，功能最完整，且不依赖 Shizuku 服务。
- 设备未 Root：选择 **Shizuku 版**。

## Shizuku 版的使用须知

- **需要保持 Shizuku 运行。** 应用本身不具备系统权限，所有清理均经由 Shizuku 完成；Shizuku 未运行或未授权时，应用会给出提示，定时清理不会执行。
- **重启后的行为取决于 Shizuku 的启动方式。** 通过 Root 启动的 Shizuku 在开机后自动可用，CZeroX 会随之恢复定时任务；通过 ADB 启动的 Shizuku 在每次重启手机后都会停止，需要重新启动一次，之后定时任务才会恢复。
- **ADB 启动时无法清理应用内部数据目录。** 以 ADB 方式获得的权限低于 Root，规则中指向应用内部数据目录的路径不会生效，其余路径不受影响。状态页会显示当前的权限级别。
- **状态与维护。** 应用的状态页可查看 Shizuku 服务、授权状态与清理守护进程是否正常，并提供「申请授权」与「重新部署」入口；定时任务意外停止时，重新部署即可恢复。
- **卸载。** 卸载后可在 Shizuku 的授权列表中撤销本应用的授权。

其余功能的用法与 Root 版一致，详见[功能详解](/guide/features)与[配置参考](/guide/configuration)。
