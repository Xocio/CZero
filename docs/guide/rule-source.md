# 开发规则源

规则源让任何人都能维护并分发自己的清理规则。它就是一个托管在 HTTP 上的 JSON 文件，用户在 CZeroX 里填入链接即可订阅，之后**每天自动更新一次**。

::: tip 面向谁
这篇文档写给想向 CZero 用户发布规则的开发者。**推荐自建仓库**维护规则源，CZero 仓库也留了一个备用的存放位置。

只是想加几条自己用的路径，请直接在 CZeroX 的「自定义规则配置 → 模块内置规则」里添加，不用做规则源。
:::

## 文件格式

规则源和模块本地的 `clean_paths.json` 是同构的，只在顶层多了署名信息：

```json
{
  "name": "老王的规则源",
  "author": "@laowang",
  "version": "2026.08.04",
  "homepage": "https://github.com/laowang/czero-rules",
  "groups": [
    {
      "name": "微博",
      "enabled": true,
      "paths": [
        "/storage/emulated/0/Android/data/com.sina.weibo/cache",
        "/data/data/com.sina.weibo/files/weibo_log"
      ]
    },
    {
      "name": "小红书",
      "paths": [
        "/storage/emulated/0/Android/data/com.xingin.xhs/cache/*"
      ]
    }
  ]
}
```

把自己在 CZeroX 里整理好的规则导出，补上 `name` 和 `author`，就是一个可用的规则源。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | **是** | 源名称，显示在用户的规则源卡片标题上。超过 64 字符会被截断 |
| `author` | string | 否 | 作者署名，显示在标题下方。上限 64 字符 |
| `version` | string | 否 | 版本标识，随便用什么格式，日期最直观。上限 32 字符 |
| `homepage` | string | 否 | 项目主页。上限 256 字符 |
| `groups` | array | **是** | 规则分组，至少要有一条有效路径 |

缺少 `name`，或者 `groups` 里挑不出任何合法路径，添加时都会被拒绝。

## groups 字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `name` | string | 否 | 分组名。留空则显示为「未分组」 |
| `enabled` | bool | 否 | **缺省为 `true`**。写 `false` 表示这一组默认不生效，用户可以在应用里打开 |
| `paths` | array | **是** | 该组的清理路径 |

分组只是给人看的组织方式，清理时会被摊平。但请认真分组——用户是按分组来启停和浏览规则的，一个源里把几百条路径全塞进一个组会很难用。

## 路径写法

路径**必须是绝对路径**，支持 glob 通配：

| 写法 | 含义 |
|---|---|
| `*` | 匹配单层里的任意字符 |
| `?` | 匹配单个字符 |
| `[abc]` | 匹配字符集里的一个 |
| `**` | 递归匹配任意层级目录 |

几个常见的起点：

```
/storage/emulated/0/Android/data/<包名>/     应用外部私有目录
/data/data/<包名>/                           应用内部数据目录
/data/user/0/<包名>/                         同上，多用户路径写法
/data/media/0/                               等价于 /storage/emulated/0
```

::: warning 目录会被递归清理
写一个目录路径，意味着**该目录下所有文件**都会被清掉，然后连空目录一起删除。务必精确到 `cache`、`log` 这类真正的缓存目录，不要写 `files` 这种可能装着用户数据的父目录。
:::

## 会被拒绝的路径

拉取时逐条校验，不合规的**单条丢弃**，不会让整个源失败：

- 不是以 `/` 开头的相对路径
- 路径里含有 `..`（防止回溯到目标之外）
- 长度超过 512 字符，或短于 2 个字符

## 体量限制

| 限制 | 数值 | 超出后 |
|---|---|---|
| 文件大小 | 2 MB | 整个源被拒绝 |
| 路径条数 | 5000 条 | 超出部分被丢弃，前 5000 条正常生效 |

## 托管

### 推荐：自建仓库

任何能返回 JSON 的 HTTPS 地址都可以。最省事的做法是开一个自己的 GitHub 仓库：

1. 新建一个公开仓库，比如 `你的用户名/czero-rules`
2. 把规则文件放进去，例如 `rules.json`
3. 用 raw 链接分发：

```
https://raw.githubusercontent.com/<用户名>/<仓库>/main/rules.json
```

响应必须是裸的 JSON 文本。注意 GitHub 的**网页地址**（`github.com/.../blob/...`）返回的是 HTML 页面，不是 JSON，用户填了会报「文件不是合法的 JSON」。

::: warning 只收 http/https
`file://`、`content://` 之类的协议一律拒绝。
:::

自建的好处是你完全掌握自己的规则：什么时候更新、更新什么都不用等别人；用 Git 管理规则，改错了能回滚，用户提 issue 你能对着 diff 看。发布时记得同步更新 JSON 里的 `version`，用户在应用里能看到版本变化。

::: tip 不用担心访问次数
`raw.githubusercontent.com` 的限流是**按访问者 IP** 算的，不是按仓库算的，所以你的仓库被多少人订阅都不受影响。而且每个用户每个源一天只拉一次。
:::

### 备用：放到 CZero 仓库

实在不方便自己维护仓库，可以开一个 [issue](https://github.com/Xocio/CZero/issues) 申请把 JSON 放到 CZero 仓库的 `rules/public/` 目录，地址是：

```
https://raw.githubusercontent.com/Xocio/CZero/main/rules/public/<文件名>.json
```

::: warning 仅代为存放
CZero **不审核**规则内容，放在这里不代表经过检查或获得背书，规则的正确性与安全性仍由作者本人负责。这只是给没有条件自建仓库的人留的路，能自建就自建。
:::

## 订阅

CZeroX → 设置 → 自定义规则配置 → 右上角 `⋯` → 添加规则源 → 粘贴链接。

添加成功后会多出一张卡片，标题是源里的 `name`，副标题是 `author`，卡片上能看到分组数、规则数和上次更新时间。点卡片进去可以逐条查看。

## 更新机制

- 用户打开规则源页面时，若距上次同步超过 **24 小时**，会自动拉取所有已启用的源
- 也可以在卡片上点刷新图标手动更新
- 更新时该源名下的规则**整体替换**：以你的源文件为准
- 重复添加同一个 URL 视为更新，不会产生两张卡片

::: warning 用户的本地改动会被覆盖
用户可以在本地增删改你的源规则（比如临时停用某一组），但这些改动会在下次更新时被源文件冲掉——归属由 JSON 里的 `source` 键决定，更新只认源文件。这是设计如此，用户想长期保留的改动应该放到内置规则里。
:::

## 执行

你的规则会和内置规则一起交给 `list/customize` 处理，行为完全一致：

- **回收站**：匹配到的文件是被移入 `/storage/emulated/0/Recycle`，不是直接删除，用户可以恢复，默认保留 7 天
- **时序屏障**：若用户开启，只有修改时间早于 N 天的文件才会被清理
- **白名单**：用户的 `clean_whitelist.json` 优先级更高，命中白名单的路径会被跳过
- **嵌套去重**：父目录已在清理列表里时，它下面的子路径会被自动忽略

所以不必担心写重复，但要担心写宽——写错一条能删掉用户的数据。

## 建议

1. **先在自己设备上验证**。把规则填进 CZeroX 的内置规则跑一轮，确认清理量和应用行为都正常，再发布。
2. **只清可再生的数据**。缓存、日志、崩溃转储、临时下载是安全的；聊天记录、草稿、下载目录、账号凭据不要碰。
3. **分组按应用切**。一个应用一组，组名用应用中文名，用户才好按需启停。
4. **改动时更新 `version`**。用户看不到 diff，但能看到版本号变化。
5. **谨慎使用 `**`**。递归匹配在大目录上既慢又容易误伤。
6. **默认停用有风险的组**。拿不准的规则写 `"enabled": false`，让用户自己决定要不要开。
